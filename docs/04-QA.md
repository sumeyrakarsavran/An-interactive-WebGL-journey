# SIRR — Phase 5: Integration & QA report

All numbers come from the automated walkthrough (`tools/qa-walkthrough.mjs`). It ran against the **production build** in headless Chrome with the GPU enabled. On this test machine Chrome picked the **Intel UHD integrated GPU** (Direct3D 11 via ANGLE), not the discrete RTX. That makes these figures a deliberately strict, mid-range-laptop / tablet-class baseline. Frame rates are capped at 144 by the display loop.

## How to reproduce

```bash
npm run build                              # static export to out/
node tools/serve-static.mjs out 3100
node tools/qa-walkthrough.mjs http://localhost:3100 qa-out high,medium,low          # desktop 1440×900
node tools/qa-walkthrough.mjs http://localhost:3100 qa-out low mobile               # 390×844, touch, DPR 3
node tools/qa-leak.mjs        # three full loops through all chapters; GPU memory must stay flat
node tools/qa-leak-each.mjs   # per-chapter GPU memory diff
node tools/qa-a11y.mjs        # reduced motion, keyboard, reading mode, screen-reader hiding
node tools/qa-faults.mjs      # chunk download failure, GPU context loss and restore (Phase 6)
```

`?qa=1` exposes the store and renderer to these scripts in production (always on in development). It changes nothing else.

- **No black or NaN frames** at any tier. Dark pixels in Nefs and the night lake are the scenes' own darkness, confirmed by mean luminance.

- **Accessibility:** 8/8 checks pass.

## What Phase 5 changed

| Problem found | Fix |
|---|---|
| **853 ms freeze** crossing Nefs → Zaman; 100–230 ms freezes at other thresholds. Shaders of the next chapter were compiled at the moment of the swap. | The pre-mounted neighbour chapter is compiled in the background with `renderer.compileAsync` (`KHR_parallel_shader_compile`). Worst threshold now 63–83 ms on *high*, 0 hitches on *low*. |
| **GPU memory leak:** +7 geometries / +11 textures per journey. | Each chapter collects every geometry, material and texture beneath it (every 250 ms, from mount) and disposes them on unmount. drei's `MeshReflectorMaterial` (internal blur targets nobody can dispose) was replaced by our own `Reflector` floor. drei's `<Environment>` (leaked a cube map per remount) was replaced by a PMREM dawn map built once and cached. |
| Nefs at 44–50 fps on *high* (integrated GPU). | Mirror MSAA removed (the tarnish blur hides aliasing). Lighter floor reflection. Now 56–64. |
| Machines with a strong CPU but an integrated GPU were placed on *high*. | `detectTier` reads the unmasked GPU name. Intel, Mali, Adreno, PowerVR and software renderers start at *medium* at most. `PerformanceMonitor` still steps down at runtime. |
| Chapter index / "Şafağa dön" smooth-scrolled through every chapter in between, mounting each one. | Jumps go through a short dark **curtain**: fade out, move instantly (camera teleported too), fade in. Number keys **1–6** jump the same way. |
| Ivory text unreadable over bright petals and sand. | A soft radial scrim fades in behind whatever is being said. Controls get a text shadow. |
| No alternative to the WebGL experience except when WebGL is missing. | **Reading mode** ("Metin"): the whole journey as text, with sources, and the canvas paused. The canvas and overlay are `aria-hidden`; screen readers get the text journey. |
| One wind sound for every chapter. | Per-chapter procedural soundscapes that crossfade: wind / airy / near-silence / wind with a distant galloping pulse / lapping water with a soft tone per drop / morning air. Off by default. |
| On phones the chapter index overlapped the controls. | Index moves to the top on narrow screens; safe-area insets respected. |
| 404 in the console (no icon). | `app/icon.svg`. |

## Phase 6 re-check (static export)

The final static export (`out/`, served by `tools/serve-static.mjs`) was re-run with the walkthrough at *medium*, the failure drills, accessibility and memory checks.

- **Function:** all pass. No black frames, no console errors, 8/8 accessibility, flat GPU memory, 4/4 failure drills (chapter download blocked, GPU context lost and restored).
- **Frame rate is not comparable to the table above.** The laptop was then on battery at 14%, and the integrated GPU was throttled to about 30 fps for any WebGL content (an empty page still ran at 82). Always check the power state before reading frame rates. `node tools/qa-baseline-fps.mjs` gives the empty-page baseline.

## Not covered by this pass (needs people or devices)

- **Real phones:** iOS Safari and Android Chrome, touch feel, thermal throttling over a full visit. The mobile run is a viewport emulation on a desktop GPU.
- **Safari and Firefox:** not available on this machine. Watch for `HalfFloatType` render targets (ripple simulation, reflections) and `KHR_parallel_shader_compile` (missing in Firefox: compilation then happens synchronously, as before).
- **Sound:** the profiles were written and wired up but not listened to in this session (headless).
- **Theology review:** every summary, hadith number and scholar entry in `src/content/sources.ts` still needs a qualified reviewer. Meal text must come from a licensed source.
- **Assets:** flowers, figures, tree and mirror are procedural. Blender hero assets would raise visual quality (see `03-ASSETS.md`).
